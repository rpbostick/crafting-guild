## Requirements (Patrick, 2026-10-01)
- A private fan rules text for running games in *The Painted Wastelands*, built from *World of Dungeons* 1979 (WoD), *World of Dungeons: Remix* (Remix) and *Advanced World of Dungeons* (AWoD).
- v1: merge all three texts into one document, sections in a logical order, every passage tagged with its game. Keep most of the information from each; where classes, skills or abilities differ, keep all of them, creating new classes if needed. Names to be discussed with Patrick.
- Show it as a side-by-side diff tool: sections with suggested changes highlighted, an Accept button per suggestion, and the discussion of contradictions.
- Keep original text and art in the private project. Licence information for each source, so the eventual public game knows what it may use and what it must rewrite.
- v2 (later): *Electric Bastionland* rules that differ, its spells, oddities and equipment; Failed Careers in the character generator, keeping WoD's gameplay; *The Painted Wastelands*. Research how the Into the Odd / Electric Bastionland engine is licensed for derivatives (Cairn and others).

## Next after step 3 merges: a general synthesis tool (Patrick, 2026-10-01)
Its own repo and workspace project: `~/synthesis-tool`, private GitHub remote (public later only after `release-audit.md`). Usage: a CLI (`synth extract` PDF→text, `synth check` format + coverage, `synth build` → self-contained review page with db-backed decisions and notes) plus a builder task template for writing a synthesis from any set of sources. Extract from pen-paper-rpg: `scripts/synthesis-format.js`, `scripts/check-coverage.js`, `site/*`, `scripts/build-review.js`, their tests; example data made up, no game text. pen-paper-rpg then uses the tool instead of its own copy. Start it while Patrick works in the review page. Prior-art check (2026-10-01): nothing found that merges *different* texts by topic with accept/reject and notes. Collation tools (Juxta, CollateX) align versions of the *same* text, so they don't fit this job, though they're worth noting for comparing editions. Reuse: **jsdiff** (BSD-3-Clause, `diffWords`, has a browser build) in place of the hand-written diff; a Markdown library (e.g. marked) inlined at build time in place of a hand-written renderer; consider **CriticMarkup** syntax for inline edit marks inside proposals. Creating the GitHub repo is outward-facing: confirm the repo name with him first.

## Block format (shared by steps 2 and 3)
`rules/v1/synthesis.md`: `#` title, `##` sections, optional `###` subsections. Inside sections, fenced blocks:
```
::: source wod p1
verbatim text
:::
::: proposal id=classes-fighter
proposed merged text (Markdown)
:::
::: discussion id=classes-fighter
why; what contradicts; options
:::
```
Sources: `wod`, `remix`, `awod`, with the PDF page. Every proposal has a discussion with the same id; ids are unique.
