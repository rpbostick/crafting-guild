## Running builders
- Parallel builders share the CPU: a render-heavy builder alongside a merge made the merge's suite two to three times slower (colorwright, 2026-09-26). The usage limit killed four builders at once on 2026-10-05 23:26; `ws wait` writes the result since 2.3.3, and `ws chain` waits for the reset since 2.2.4. Parallel jest workers were SIGKILLed at the builder memory cap (2026-10-04).
- A missing grant stalls a builder silently: bw-export-screen ended partial on `npx expo install` under an `npm install *` grant (2026-10-07), an hour after the audit named grants the most recurrent defect. The builder git and file grants date from 2.3.2.
- Two sessions, two projects: `state/current` is one file, so the second `ws <slug>` moves it under the first. Sessions are pinned by `WS_PROJECT` since 2.1.2, but a session started any other way is not; when cold-start prints `CONFLICT` or `not pinned`, use `--project` on every command (found 2026-09-27 testing 2.1.0 from a terminal).
- Review once per branch, before merge. A fix round is for a real defect or something he would see; suggestions carry forward in the next task on that code.
- The machine has 14 GB and no swap: a spike's probe script reached 7.6 GB and the OOM kill took down VS Code with the orchestrator and both builders (fw-bodyshape, 2026-09-27); builders are capped since 2.1.3. Before previews were capped, `expo start --clear` started a Metro worker per core (16, ~700 MB each), and a second preview started beside :8805 OOM-killed the desktop session (2026-10-08).
- Hard crash 2026-10-12 12:57 with three retrowright builders running (14 GB, 4G caps each, a `tsc` and ~80 clones going; no OOM logged): five empty git objects on rw-cores-spike's commit, an Edit left as `QuickMenu.test.tsx.tmp.*`. - **Two orchestrators at once (open investigation, 2026-09-28).** When a session closed at 16:42, Claude Code's daemon forked it into a background session (`claude daemon run --origin transient` → `--fork-session --resume <old id>`); the new `ws bike-weather` window started 4 s later. For 16 hours both acted on figurewright: two reviews of fw-dress, a fix round dispatched by the background one. Patrick had one window open. Until explained: on resume, also run ListAgents. Seen again 2026-10-01 ~16:10 MDT (CLI 2.1.286): after Patrick closed a `ws figurewright` session, the daemon resumed it as `bg-pty-host … --fork-session --resume`, woken by a `ws wait` finishing; the fork stood down. To find out: what makes the CLI background a closing session (a setting, a running `ws wait`, auto mode?), and whether cold-start should detect a peer. VS Code's Claude extension resuming its last panel conversation on open (`native-binary/claude … --resume=<id>`, parent `code`, cwd `~`) idles at $0; only a `--fork-session` process or one whose cwd is this workspace counts (2026-09-29).
- Closing or crashing the session kills its background `ws wait`: a chain whose log ended in `Terminated` died with it too (figurewright, 2026-10-07).
- Bash reads a running script from disk as it goes: found editing `scripts/chain.sh` under a running chain (2026-10-01).
- Never `pgrep -f`/`pkill -f` a pattern that appears in your own Bash command: a wait loop spun for 10 minutes and a `pkill` killed its own call (2026-09-29).
- A background `ws wait` is killed at the Bash tool's default 30-minute background limit; pass `timeout` up to 7200000 for long runs (2026-10-02, a 180m round's wait died at 30 min).
- Mark small, low-risk tasks `Track: light`: a two-outfit colour split took an hour of process (Patrick, 2026-09-26).
- The timeout follows the track: a timed-out run died without writing its result (cw-p20-2b, 2026-09-27).
- Reuse before building (Patrick, 2026-10-01): the synthesis review page was dispatched with a hand-written diff while jsdiff exists.
- Check a premise before writing a task on it: "Open-Meteo times shift at DST" (skywright, 2026-09-27) and "gate on `'oncancel' in input`" (bike-weather, 2026-10-07; every element has had `oncancel` since `<dialog>`) each cost a fix round.
- Repos state reasons, never who or when: builders copied task wording ("Patrick, 2026-09-29", "the operator: …") into ~800 comment lines across colorwright and figurewright, scrubbed 2026-09-29.
- `ws chain` skips a queue step whose name was merged: skywright's new `sky-demo` step never ran and the chain said done (2026-10-04).

- A project that depends on a sibling by `file:../<name>`: bike-weather on skywright; without the `.worktrees/skywright` link (first made by hand, 2026-10-06) Metro, the web export and `ws serve <name>` fail there.
- A builder worktree whose `node_modules` is a symlink to the main checkout shares Metro's transform cache: `ws serve` of a second bike-weather worktree showed expo-router's "Welcome to Expo" because the cached entry pointed at the removed bw-templates worktree's `src/app` (2026-10-06).
- Switch course on the second partial run of one task name: fw-shoulders-build ran 8 times over 4 days ($84) after Patrick stated the chest-to-shoulder rule on day one; site-waves-momentum took 9 builder rounds for a few parameters (audit, 2026-10-06). The done-when is his one-sentence fault verbatim.
- retrowright SMB builders working on SMBDIS copies inside `.ws-evidence/scratch/` cannot delete them (`git clean -fx` denied) and leave them, even "emptied" ones with content, where `ws merge` archives evidence (rw-smb-board-big, 2026-10-14). - A task that tells a builder to `git merge <branch>` must list `git merge *` in its Commands: rw-smb-tricks (2026-10-15) was denied and copied the files in with no merge parent; the orchestrator repaired it with `git merge -s ours` after checking the files matched.
- A Vite dev server left running across a dependency upgrade on its checkout serves a blank page: its pre-bundled deps go stale ("blocked because of a disallowed MIME type" in the console) while the ROM folder still answers. Restart it (`ws serve stop main`, `ws serve main 8800`) after any merge that changes package.json, and load the link headlessly before sending it (retrowright :8800 after the vitest upgrade, 2026-10-16).
- Never put "the project test command passes in full" in a done-when: builders are told the merge gate runs it, and skate-mario's SMB tests need RETROWRIGHT_* variables builders cannot set (`env` is denied), so the run ends partial on a check the gate does anyway (sm-homebrew-scroll, 2026-10-16). Name the test files the change covers instead.
- A suite near its per-test timeout fails a merge on a branch that only adds tests (sm-ramp-launch, 2026-10-20: two gate failures, all timeouts; main alone also timed out once at 224 s). Run main's and the branch's suite yourself before blaming load; the fix is a light test-speed task. skate-mario builders run the SMB tests only with a git-ignored `.env.local` in their worktree (written by dispatch from the conf's `WORKTREE_ENV`).
