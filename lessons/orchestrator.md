## Working with Patrick
- Present decisions with the AskUserQuestion prompt: recommended option first and labelled, at most four per call, in rounds. He usually answers "all recommended". Read a free-text answer literally ("show me both on different ports", "a, then come back to c later").
- Ask before any infrastructure change (replacing a layer, adding a service, changing how builders are launched). He wants to be in the loop.
- Every date and time you write comes from `date` run in the same step (`TZ=$WS_TZ date` only when `config.sh` sets `WS_TZ`). After 18:00 local, the UTC date is already tomorrow.
- He checks visual changes himself on a preview server before the merge. Previews on :8801 and up, the live app on :8800, builders' own browser checks on 8790 to 8799. Pages made for him to look at (comparisons, review pages) are served the same way from the scratchpad (`python3 -m http.server 88xx --directory …`), not published as claude.ai artifacts (2026-10-01); a tool he uses from several computers with saved state is the exception (private artifact with `db`). Every preview: ask with AskUserQuestion whether to open it in his browser, and on yes run `firefox --new-tab <url>` (Patrick, 2026-10-01).
- Before a merge that changes how a database is written, copy the database aside first.
- A test-count claim cites the log it came from.
- Nothing goes public without `release-audit.md` passing and Patrick seeing the findings. colorwright's static build shipped dated comments quoting him to the public site (2026-09-28).

## Running builders
- Parallel builders share the CPU, not only the plan. Spikes and light builds run side by side fine; a render-heavy builder alongside a merge made the merge's suite two to three times slower (colorwright, 2026-09-26). The usage limit kills every running builder at once, sometimes with the wrapper that writes the result (four on 2026-10-05 23:26; `ws wait` writes it since 2.3.3); their work stays in the worktrees: `ws chain` waits for the reset and resumes the run (2.2.4); outside a chain, re-dispatch after the reset with a task that says to resume. Merge when nothing heavy is running, and every dispatch gets a budget. Builders run a whole suite with `npx jest --runInBand`: parallel jest workers are SIGKILLed at the builder memory cap (2026-10-04).
- A missing grant stalls a builder silently. Name every command the task needs and pass extras with `--allow`, spelled as the task spells them: `npm install *` does not cover `npx expo install` (bw-export-screen ended partial on it, 2026-10-07, an hour after the audit named grants the most recurrent defect; tool fix to make: dispatch grants every backticked command in a task's `## Commands` section). Tell the task to use one command per Bash call. Since 2.3.2 every builder has `git restore`, `git clean -f -- <path>`, `git ls-tree` and `stat`; plain `rm` and `mv` are still denied. `cp` from outside the worktree is denied even with `--allow "Bash(cp *)"`: copy cross-repo assets in yourself before dispatch. Flags go before the builder name.
- Two sessions, two projects: `state/current` is one file, so the second `ws <slug>` moves it under the first. Sessions are pinned by `WS_PROJECT` since 2.1.2, but a session started any other way is not; when cold-start prints `CONFLICT` or `not pinned`, use `--project` on every command (found 2026-09-27 testing 2.1.0 from a terminal).
- Review once per branch, before merge. A fix round is for a real defect or something he would see; suggestions carry forward in the next task on that code.
- `ws merge` needs the project's main checkout free of modified tracked files; untracked files are fine. Check `git status -uno` first. It can take over 10 minutes when builders run alongside: run it with `run_in_background`.
- `ws merge` refuses any verdict but `merge`. When Patrick overrides a fix-first review, pass `--no-review` (the SHA pin and the test gate still apply) and record his decision in the plan.
- The machine has 14 GB and no swap. A spike's probe script reached 7.6 GB and the OOM kill took down VS Code with the orchestrator and both builders (fw-bodyshape, 2026-09-27). Builders are capped at `WS_BUILDER_MEM` since 2.1.3; tell image-processing spikes to hold one raster at a time.
- A builder that backgrounds a long script loses it when the run ends (cw-heads-spike part 2, 2026-09-26). Tell spikes with long render jobs to run them in the foreground, split if needed.
- **Two orchestrators at once (open investigation, 2026-09-28).** When a session closed at 16:42, Claude Code's daemon forked it into a background session (`claude daemon run --origin transient` → `--fork-session --resume <old id>`); the new `ws bike-weather` window started 4 s later. For 16 hours both acted on figurewright: two reviews of fw-dress, a fix round dispatched by the background one. Patrick had one window open. Until explained: on resume, run ListAgents and `ps -eo pid,args | grep fork-session`; a peer orchestrator on this workspace means stop and tell Patrick. Seen again 2026-10-01 ~16:10 MDT (CLI 2.1.286): after Patrick closed a `ws figurewright` session, the daemon resumed it as `bg-pty-host … --fork-session --resume`, woken by a background-task notification (a `ws wait` finishing); the fork stood down. To find out: what makes the CLI background a closing session (a setting, a running `ws wait`, auto mode?), and whether cold-start should detect a peer. Not a peer: VS Code's Claude extension resuming its last panel conversation on open (`native-binary/claude … --resume=<id>`, parent `code`, cwd `~`); it idles at $0. Only a `--fork-session` process or one whose cwd is this workspace counts (2026-09-29).
- Closing or crashing the session kills its background `ws wait`, not the builder (its own systemd scope): after a resume, read `runs/<slug>/<name>.result.txt` or wait again. A chain whose log ends in `Terminated` with no `runs/<slug>/chain.pid` died with it too (figurewright, 2026-10-07): re-run `ws --project <slug> chain <queue>`; it skips merged steps and waits on the run in progress. `ws chain-wait` only waits on a live chain. A resumed session gets a new scratchpad, so rebuild any review page there.
- Bash reads a running script from disk as it goes: editing `scripts/chain.sh` (or any script) in place while a chain runs can make it execute shifted text. Write the new version to a temp file and `mv` it over (2026-10-01).
- Never `pgrep -f`/`pkill -f` a pattern that appears in your own Bash command: it matches the shell running it (a wait loop spun for 10 minutes; a `pkill` killed its own call, 2026-09-29). Run parallel jobs with `&` and `wait`, and kill by PID.
- A background `ws wait` is killed at the Bash tool's default 30-minute background limit; pass `timeout` up to 7200000 for long runs (2026-10-02, a 180m round's wait died at 30 min).
- Mark small, low-risk tasks `Track: light` (code + unit tests, no evidence ceremony; the merge gate runs the suite). Evidence formatting doesn't block reviews; `ws merge` refuses a branch that adds home paths or the username, so scrub them on the branch first. (Patrick, 2026-09-26: a two-outfit colour split took an hour of process.)
- The timeout follows the track: 45m for `Track: light`, 120m otherwise (`config.sh`); pass `--timeout` (minutes, or `2h`) for a bigger build and `ws wait <name> <minutes>` to match. A timed-out run can die without writing its result (cw-p20-2b, 2026-09-27): check `git log` and `git status` in the worktree, then resume.
- Builders run only the tests for what they touched (v2.1.0); the merge gate runs the suite. `ws merge` prints the suite's time and warns over `WS_SUITE_WARN_S`; when it warns, a light task to speed up the slowest test files is the next thing to dispatch.
- Reuse before building (Patrick, 2026-10-01): research existing open-source programs and libraries before any build, more research the bigger the build: minutes for a small change, a research spike before a new tool or a substantial module. Every build task carries a `## Prior art` section; `ws dispatch` warns when it is missing. (The synthesis review page was dispatched with a hand-written diff while jsdiff exists.)
- Check a provider's real behaviour before writing a fix task about it: a task premise ("Open-Meteo times shift at DST") that was never verified cost a fix round (skywright sky-ride, 2026-09-27). A live or historical API call takes a minute.
- Repos state reasons, never who or when; plans keep attribution. Builders copied task wording ("Patrick, 2026-09-29", "the operator: …") into ~800 comment lines across colorwright and figurewright, scrubbed 2026-09-29. Write task requirements plainly; dispatch and merge now refuse attribution (`WS_ATTRIBUTION_RE`).
- Public releases of a private repo go through `ws release` (2.3.0): it audits the new lines, commits main's exact tree on `public-release`, tags and builds from a clean clone. Setting one up: create the public GitHub repo, `git remote add public <url>`, and run it; the first release is an orphan commit.
- A queue step whose name was ever merged in that repo is skipped as "already merged" (skywright `sky-demo`, 2026-10-04: the new demo step never ran and the chain said done). Check `git log --merges | grep agent/<name>` before reusing a short name.
- Before a task states which frame, joint set or registration to use, have the builder measure the candidates first (figurewright fw-found-art, 2026-10-05: two runs, about $38, on registrations I named from reasoning; the builder's measured third option was the right one).
- A JS project's jest config must scope `roots` to its source (or ignore `/.worktrees/`): the merge gate runs from the main checkout, where every builder worktree is a copy of the repo, so jest collects each test twice and the copy fails on duplicate React (bike-weather skeleton, 2026-10-05). Check this in `ws init` output for new JS projects.
- A project that depends on a sibling by `file:../<name>` (bike-weather on skywright): once a builder runs `npm install` or `npx expo install`, its worktree gets its own node_modules and the relative link points into `.worktrees/`, so Metro, the web export and `ws serve <name>` fail there. Keep a symlink `<project>/.worktrees/<name>` → the sibling (made for skywright 2026-10-06); jest and tsc pass without it, which hides the break.
- A builder worktree whose `node_modules` is a symlink to the main checkout shares Metro's transform cache with every other worktree: `ws serve` of a second worktree showed expo-router's "Welcome to Expo" because the cached entry pointed at the removed bw-templates worktree's `src/app` (bike-weather, 2026-10-06). `PREVIEW_CMD` now passes `--clear`; a builder's `expo export` in such a worktree is exposed the same way.
- Switch course on the second partial run of one task name, or the third feel-tuning round of one page: change the task (his one-sentence fault as its done-when verbatim, measure first, a slider page he tunes live), not the budget. fw-shoulders-build ran 8 times over 4 days ($84) after Patrick stated the chest-to-shoulder rule on day one; site-waves-momentum took 9 builder rounds for a few parameters (audit, 2026-10-06).
